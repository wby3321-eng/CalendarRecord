# CalendarRecord 技术架构与方案

---

## 一、总体架构

```
┌─────────────────────────────────────────────┐
│  浏览器 SPA (响应式, PC/移动)                  │
│  日历格子 · 起始日卡片 · 跨天甘特跨度 · 搜索 · AI悬浮球 │
└───────────────┬─────────────────────────────┘
                │ HTTPS / REST + SSE(AI流式)
┌───────────────▼─────────────────────────────┐
│  后端 API 服务 (FastAPI)                       │
│  Auth · Tasks · Types · Files · AI-Proxy      │
│  (JWT鉴权 · 数据按 owner_id 隔离 · 注册限流)    │
└───────┬──────────────┬───────────────┬───────┘
        │              │               │
┌───────▼──────┐ ┌─────▼──────┐ ┌──────▼────────┐
│ SQLite       │ │ 本地卷      │ │ 智谱 GLM API   │
│ (JSON扩展字段) │ │(图片/文档)  │ │ (后端硬编码密钥)│
└──────────────┘ └────────────┘ └───────────────┘
        全部容器化，Docker Compose 部署于单台云主机
```

## 三、前端方案

**模块**：品牌顶栏（logo + 标题/副标题 + 角色 pill + 用户切换 + 退出）、工具栏（视图切换/日期导航/搜索/延期阈值）、类型 chip 栏、日历容器（周/月/自定义视图切换）、任务卡片、任务编辑抽屉（默认字段 + 动态扩展字段）、类型管理、AI 分析悬浮球 + 面板。

**关键难点 → 对策**

- **多视图网格（格子布局）**：统一以「日期数组」驱动渲染，周历=7 格、月历=整月按周分行、自定义=起止区间；周一为首用 day.js `isoWeekday`；每天一个较高格子（cell），格子内可竖直堆叠任务卡片。
- **任务定位（混合范式）**：任务卡片按 `plan_start_date` 落位到对应格子内显示（丰富卡片：状态圆点/类型 icon/标题/🔗/优先级三色 pill/延期徽章/结论预览/聚合 owner 标签）；**跨天任务在此基础上额外渲染横跨 `plan_start_date~plan_due_date` 的甘特跨度条**（仅用于展示跨度，需求 §85/§87），跨行分段续接。
- **三种拖拽语义**（需求5 / 业务规则）：
  - 拖**主体** → start 与 due 同步平移；若整体后移 → `reschedule_count += 1`。
  - 拖**右缘** → 只改 `plan_due_date`（不计延期），形成甘特跨度。
  - 拖**左缘** → 只改 `plan_start_date`（不计延期）。
- **延期高亮**：`未完成 && (今天 > plan_due_date || reschedule_count >= 阈值)` 时高亮；有次数显示「图标+数字」，无次数仅显示图标。
- **搜索**：前端解析 `status:done type:plan` token（可多值）+ 剩余文本对 名称/链接/结论 模糊匹配，组合取交集后传后端查询。

**视觉设计（以 `docs/index.html` 原型为基准）**

- **品牌顶栏**：渐变圆角 logo + 标题「CalendarRecord」+ 副标题「个人成长日历记录平台」+ 角色 pill +（管理员）用户切换 + 退出；工具栏独立成行。
- **设计 token**：蓝色主色系（#2563eb 系）、多层阴影（shadow / -md / -lg）、hover 上浮、圆角 10px、优先级三色 pill（高红/中黄/低蓝）、状态圆点（已完成 ✔）、延期红描边 + 徽章、modal pop 动画；由 Tailwind theme 扩展统一承载。
- **AI 入口**：右下角渐变悬浮球 FAB → 模态面板。
- **响应式**：PC/移动断点自适应，保持通用蓝色 SaaS 风格。

Vite启动项目->用React组件+Tailwind样式搭界面->TanStack Query找后端要数据->TS全程帮查错

## 四、后端方案

**API 分组**（全部校验 JWT，查询强制带当前 `owner_id`；管理员可跨用户）：

- `Auth`：register（校验 `count(users) < 5` 否则拒绝）/ login / me / logout
- `Tasks`：CRUD、状态切换、拖拽更新（start/due/reschedule_count）、按 token+范围查询
- `Types`：内置类型初始化 + 自定义类型 CRUD + 扩展字段定义
- `Files`：上传（图片/文档），返回受保护 URL
- `AI`：接收「当前筛选后的任务集 + 选定提示词」，拼装 context，流式返回

**权限**：普通用户仅本人数据；管理员可切换/聚合查看全部（需求二）。依赖注入统一注入「当前用户」做 owner 过滤，杜绝越权。

## 五、数据模型（SQLite）

```
users        (id, username, nickname, password_hash, role,
              created_at, updated_at)
task_types   (id, owner_id NULLABLE, name, color, icon, is_builtin,
              field_defs JSON,  -- [{key,label,type}]
              created_at, updated_at)
tasks        (id, owner_id, type_id, title, link, conclusion,
              status, priority,
              created_at, plan_start_date, plan_due_date, actual_done_at,
              reschedule_count INTEGER DEFAULT 0,
              ext_fields JSON, updated_at)
attachments  (id, task_id, kind, url, filename, size, created_at)
```

- 用户名：`username` 作登录账号，注册后固定不可改（避免重名与重新登录问题）；显示用可改的 `nickname`（昵称）。
- 更新时间：`users` / `task_types` / `tasks` 均含 `updated_at`，记录最后修改时间；`attachments` 含 `created_at`（附件一般只增删不改）。
- 扩展字段：定义存 `task_types.field_defs`，数值存 `tasks.ext_fields`（JSON），满足动态字段（文本/链接/图片/文件/多行）。
- 状态/优先级用枚举；日期字段仅到「日」。
- 开 WAL 提升并发读；5 用户量级单写足够。
- 备份 = 定时复制 `db.sqlite` 或 `sqlite3 .backup`，挂持久卷。
- 所有业务查询强制带 `owner_id` 过滤（管理员角色可跨用户/聚合）。

## 六、AI 分析方案

后端接收前端**当前筛选数据**作为上下文 → 按所选预设（4 个：进度趋势 / 分布 / 阶段性复盘 / 预测）或自定义提示词拼 prompt → 调智谱 GLM（OpenAI 兼容 `/paas/v4/chat/completions`，密钥后端硬编码，默认 glm5）→ SSE 流式回传前端渲染。数据量大时对任务集做字段裁剪与条数上限保护。

## 七、部署与运维

```
Docker Compose
 ├─ caddy   :443  → 前端静态 + /api 反代到 api:8000，自动 HTTPS
 ├─ api     :8000 (uvicorn FastAPI)
 └─ volumes: ./data/db.sqlite  ./data/uploads
```

- 单台 2C4G 云主机即可；无需独立 DB 容器（SQLite 随 api 进程，库文件挂卷）。
- 数据库与上传目录挂持久卷；定期备份。

## 八、单元测试（开发负责）

> 单元测试由**开发**在编码时同步编写，聚焦纯逻辑函数/组件，隔离数据库、网络与浏览器，秒级快速运行。功能/接口/权限等测试见 `docs/测试方案.md`（QA 负责）。
> 工具：后端 pytest（`backend/tests/test_*.py`）；前端 Vitest（`src/**/*.test.ts`）。目标覆盖率：核心纯逻辑 ≥80%。

**示例**（后端 pytest，对应 UT-01）：

```python
def test_is_delayed_by_threshold():
    task = Task(status="todo", reschedule_count=3, plan_due_date="2026-07-01")
    assert is_delayed(task, today="2026-06-01", threshold=3) is True

def test_not_delayed_when_done():
    task = Task(status="done", reschedule_count=5, plan_due_date="2026-01-01")
    assert is_delayed(task, today="2026-07-10", threshold=3) is False
```
