## 一、总体架构

```
┌──────────────────────────────────────────────────────────────┐
│  浏览器 SPA（React18 + TS + Vite + Tailwind，响应式 PC/移动）    │
│  日历/搜索/报刊/标签云/AI 面板 · TanStack Query 管服务端状态      │
└───────────────┬──────────────────────────────────────────────┘
                │ HTTPS：REST（JSON）+ SSE（AI 流式）
┌───────────────▼──────────────────────────────────────────────┐
│  Caddy（:80/:443）自动 HTTPS + SPA 静态托管 + /api/* 反代         │
└───────────────┬──────────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────────┐
│  FastAPI（uvicorn :8000）                                       │
│  routers: auth / types / tasks / files / ai                    │
│  deps 注入「当前用户」→ owner_id 隔离；JWT httpOnly Cookie 鉴权  │
│  纯逻辑层 logic.py（延期/搜索/拖拽/范围/状态/限流，可单测）        │
└───────┬───────────────────┬──────────────────┬────────────────┘
        │                   │                  │
┌───────▼──────┐   ┌────────▼────────┐  ┌──────▼──────────┐
│ SQLite(WAL)  │   │ 本地卷 /data      │  │ 智谱 GLM API     │
│ JSON 扩展字段 │   │ db.sqlite+uploads│  │ (OpenAI 兼容/SSE)│
└──────────────┘   └─────────────────┘  └─────────────────┘
        单机 Docker Compose（api + caddy 两服务 + 持久卷）
```

### 3.3 关键实现点

- **多视图网格**：以日期数组驱动；周历 7 格、月历整月按周分行、自定义按起止；`isoWeekday` 周一为首。
- **混合范式定位**：任务按 `plan_start_date` 落格；跨天任务额外渲染甘特跨度条（`lane` / `card` 两模式，泳道数可配）。
- **三语义拖拽**：`CalendarView` 手写 pointer 事件 → 调 `POST /tasks/{id}/drag`（mode=body/left/right），后端 `apply_drag` 结算改期计数。
- **搜索**：前端 `parseSearch` 展示解析结果，实际过滤在后端；类型图例做本地叠加显隐。
- **标签**：读写 `ext_fields["tags"]`，`tagColor` 由文本哈希取稳定配色；标签云 `TagCloud` 螺旋填充，字号 ∝ `sqrt(count)`。
- **AI 流式**：`AIPanel` 直接 `fetch("/api/ai/analyze")` + reader 手工解析 `data: {json}\n\n` 增量渲染，`AbortController` 支持停止。
- **本地设置**：阈值 / 卡片配色 / 甘特模式 / 泳道数 / 空日期样式 / 报刊版序 / 竖栏折叠等以 `cr_*` 键存 localStorage。

## 五、数据模型（SQLite）

见 [models.py](file:///Users/wangboyun/workspace/CalendarRecord/backend/app/models.py)：

```
users        (id, username[uniq], nickname, password_hash, role, created_at, updated_at)
task_types   (id, owner_id[NULL=内置], name, color, icon, is_builtin,
              field_defs JSON [{key,label,type}], created_at, updated_at)
tasks        (id, owner_id, type_id[SET NULL], title, link, conclusion,
              status, priority, created_at,
              plan_start_date, plan_due_date, actual_done_at,
              reschedule_count, ext_fields JSON[含 tags], updated_at)
attachments  (id, task_id, kind[image/file], url, filename, size, created_at)
```

- 扩展字段：定义存 `task_types.field_defs`，取值存 `tasks.ext_fields`（JSON）；**标签复用** `ext_fields["tags"]`（string[]）。
- 索引：`owner_id / type_id / status / plan_start_date / plan_due_date`。
- WAL 提升并发读；5 用户量级单写足够。删除类型经外键 `SET NULL` 保留任务。
- 备份 = 复制 `db.sqlite`（挂持久卷）。

## 六、AI 分析方案

1. 前端把当前筛选参数（view/anchor/custom_start/custom_end/q/owner_id + preset/prompt）POST 到 `/api/ai/analyze`。
2. 后端 `_query_context_tasks` 按 owner + 视图范围 + 搜索筛出上下文（上限 200 条），`_build_context` 逐条裁剪为 JSON 行（title/type/status/priority/start/due/done_at/reschedule/结论前 100 字）。
3. 4 预设（trend/distribution/review/forecast）或自定义提示词拼 messages → httpx 异步 stream 调 GLM（`{GLM_BASE_URL}/chat/completions`，默认 `glm-4-plus`）。
4. 以 `StreamingResponse`（`text/event-stream`）逐块 `data: {"delta": ...}\n\n` 回传，末尾 `[DONE]`；前端增量 Markdown 渲染。
5. 未配置密钥（`REPLACE_` 前缀）时返回友好提示而非报错。

> 注：当前 `_query_context_tasks` 仅按 status + 文本过滤，未处理 `type:` / `tag:`，与前端筛选存在偏差（见 [后端架构评估与改进方案.md](file:///Users/wangboyun/workspace/CalendarRecord/docs/后端架构评估与改进方案.md) B1）。

## 七、部署与运维

见 [docker-compose.yml](file:///Users/wangboyun/workspace/CalendarRecord/docker-compose.yml) + [Caddyfile](file:///Users/wangboyun/workspace/CalendarRecord/Caddyfile)：

```
Docker Compose
 ├─ caddy  :80/:443  →  前端静态 + /api/* 反代 api:8000，自动 HTTPS（SITE_ADDRESS）
 ├─ api    :8000     →  uvicorn FastAPI；DATA_DIR=/data
 └─ volumes: cr_data(/data: db.sqlite + uploads)、caddy_data、caddy_config
```

- 关键环境变量：`JWT_SECRET`、`COOKIE_SECURE`、`CORS_ORIGINS`、`ADMIN_USERNAME/PASSWORD`、`GLM_API_KEY/BASE_URL/MODEL`、`SITE_ADDRESS`。
- 单机 2C4G 云主机即可；SQLite 随 api 进程，库文件与上传目录挂持久卷。
- 生产同源部署无需 CORS；本地开发经 Vite proxy `/api → 127.0.0.1:8000`。
