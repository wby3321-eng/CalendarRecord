# 一、CalendarRecord目标与价值
**背景**： 在不同场景下，我们的目标与灵感很容易因为各种中断而丢失或被遗忘：
- **工作中**：为提升核心竞争力，我们会制定目标、实践 GitHub Trending 项目、阅读源码 / Anthropic 博客 / 书籍、参观展览等。但执行过程常被繁琐业务打断，导致忘记进度；甚至因电脑死机丢失网页，需要花费更大精力 recover。
- **生活中**：某个情景下迸发的灵感被记为 TODO，但随着七七八八的事情发生，这个 TODO 的进度早已忘得一干二净。
- **娱乐时**：刷到一篇干货满满的技术贴，为了不打断娱乐，往往把它丢进收藏夹「吃灰」。
- **换工作时**：进入新东家后，如何把前公司办公电脑里那些还未实现的 idea 重新捡起来？

**核心诉求**：
以「日历视图」为核心，统一承载计划/todo/idea/reading/收藏等多类型信息，跟踪进度与收获，支持周期性复盘，并借助AI分析历史数据辅助自我认知与行为预测。

# 三、功能需求分解

1.日历视图模块
- 三种视图：周历（默认）/月历/自定义起止日期
- 以周一为一周之首；粒度到日，不含具体时间

2.节假日/调休模块
- 法定节假日：红标「节假日名称」，节假日名称根据三方库的节假日包获取
- 调休上班日：蓝标「调休·班」

3.任务信息管理模块
- 5类内置类型（计划/todo/idea/reading/收藏等）
- 自定义类型：独立颜色+icon，支持增/改/删
- 扩展字段：内置与自定义类型均可增/改字段，字段类型含文本、链接、图片、文件、多行文本

4.任务展示与卡片
- 顶部类型chip:切换该类型显隐+显示计数，支持快捷编辑
- 每日卡片下「+新增任务」入口
- 卡片：有链接显示🔗新窗口打开；结论预览前20字符，hover显示全文；状态为已完成显示✅

5.快捷交互模块
- 状态循环切换：待办->进行中->已完成
- 拖拽调整日期：拖拽卡片主体=整体平移；拖右缘=改计划完成日（生成跨度甘特图）；拖左缘=改开始日
- 延期高亮：任务过了计划完成时间仍未完成 or 向后改期次数>=阈值（默认3，用户可自定义）且未完成时都高亮并标注延期次数（图标+数字展示即可，没有延期次数的不显示数字显示延期图标即可），完成后取消高亮

6.搜索与过滤模块
- 支持多状态联合搜索,类似GitHub的issue的搜索模式（例如：status:done type:plan），支持模糊搜索任务名称、链接、结论等字段



7.AI分析模块
- 以当前筛选数据为context
- 4个预设提示词+自定义提示词
- 输出：进度趋势/分布/阶段性复盘总结/预测报告
- 接入真实大模型密钥，默认使用智谱的glm5，后端硬编码配置即可

# 四、核心实体数据
任务实体：
- 默认字段：
    - 任务名称（必填）
    - 链接
    - 结论
    - 任务状态（枚举：待办/进行中/已完成）
    - 任务优先级（枚举： 高/中/低）
    - 创建时间（默认当前时间）
    - 计划开始时间（默认等于创建时间）
    - 计划完成时间（默认等于创建时间，根据拖拽卡片自动做相应调整）
    - 实际完成时间（标记已完成时写入）
- 扩展字段：
    - 图片
    - 文档
    - 可扩展字段
类型实体：
- 名称
- 颜色
- icon
- 扩展字段定义

用户实体：
- 账号
- 密码
- 角色

# 五、关键业务规则
- 状态三循环，可逆序切换，例如从已完成切换为进行中，从进行中切换为待办
- 跨多天任务始终视为同一个任务
- 拖拽卡片主体=整体平移，向后移动则自动计入延迟次数
- 拖拽卡片右缘时自动调整计划完成时间，不计入延迟次数，仅用于生成跨度甘特图展示
- 拖拽卡片左缘时自动调整计划开始时间，不计入延迟次数
- 在日历上按照计划开始时间显示
