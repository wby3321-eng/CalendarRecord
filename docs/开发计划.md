# CalendarRecord 开发计划

> 基于 `docs/requirement.md` 与 `docs/技术架构.md`。按里程碑推进：
> 先搭骨架 → 通鉴权/数据隔离 → 核心 CRUD → 视图与交互 → 搜索/AI → 部署与测试收尾。
> 每阶段均可独立联调验收。
>
> **日历范式（混合）**：任务卡片按「计划开始时间」定位到日历**格子内**显示（丰富卡片），跨天任务在此基础上额外生成横跨 start→due 的**甘特跨度条**（需求 §87 / §85）；非"全甘特条"渲染。
> **视觉基准**：以高保真原型 `docs/index.html` 为准（品牌顶栏、蓝色主色系、多层阴影、优先级三色 pill、延期徽章、AI 悬浮球 FAB、模态动画等设计 token）。

## M0 项目脚手架与数据模型
- 前端：Vite + React18 + TS + Tailwind 初始化，路由/请求层（TanStack Query）基础封装
- 后端：FastAPI 工程结构（APIRouter 分模块 auth/tasks/types/files/ai），Pydantic v2、依赖注入骨架
- 数据库：SQLAlchemy 模型 + Alembic 首个迁移，开启 WAL，落地 5 张表（users/task_types/tasks/attachments 及 JSON 列）
- 基础设施：Docker Compose（caddy + api + 本地卷）能本地起、健康检查通
- **验收**：`docker compose up` 后前端能访问、后端 `/health` 正常、迁移生成库文件

## M1 鉴权与数据隔离（安全底座，优先做）
- 注册（内校验 `count(users) < 5`）/ 登录 / me / logout；JWT（httpOnly Cookie）+ argon2
- 依赖注入统一注入「当前用户」，实现 `scope_by_owner()` 强制 owner_id 过滤
- 预置管理员账号；管理员可跨用户/聚合查询开关
- **验收**：越权访问被拒；第 6 个用户注册被拒；管理员可切换查看

## M2 类型与任务核心 CRUD
- 类型：5 类内置初始化 + 自定义类型（颜色/icon）CRUD + 扩展字段定义（field_defs）
- 任务：默认字段 CRUD + 扩展字段（ext_fields JSON），日期仅到「日」
- 附件：UploadFile → `/data/uploads`，下载端点校验归属
- **验收**：可建类型/任务、扩展字段可存取、附件上传下载带鉴权

## M3 日历视图与卡片展示（混合范式）
- 顶栏品牌区：渐变圆角 logo + 标题「CalendarRecord」+ 副标题「个人成长日历记录平台」+ 角色 pill +（管理员）用户切换 + 退出；工具栏独立成行
- 三视图：周历（默认）/月历/自定义，周一为首（day.js isoWeekday）
- 节假日/调休：`chinese-days`，红标节假日名、蓝标「调休·班」
- 类型 chip 栏（显隐+计数+快捷编辑）、每日格子底部「+新增任务」
- **日历采用"格子网格"布局**：每天一格；**任务卡片按 `plan_start_date` 定位到对应格子内竖直堆叠显示**（回归需求 §87 本意，非全甘特条）
- 丰富卡片：状态圆点（已完成 ✅）+ 类型 icon + 标题 + 🔗新窗口 + 优先级三色 pill（高红/中黄/低蓝）+ 延期徽章 + 结论预览前 20 字 hover 全文 +（聚合视图）owner 标签
- **跨天任务**：在起始格卡片基础上，额外生成横跨 `plan_start_date~plan_due_date` 的甘特跨度条（仅用于展示跨度，需求 §85），跨行分段续接
- **验收**：三视图切换正确、节假日标注正确、卡片信息完整、跨天任务同时具备"起始格卡片 + 甘特跨度"

## M4 快捷交互（状态 / 拖拽 / 延期高亮）
- 状态循环切换，支持**可逆序**（已完成→进行中→待办），完成写 `actual_done_at`
- 拖拽三语义：主体平移（后移 `reschedule_count+1`）、右缘改计划完成（不计延期）、左缘改开始（不计延期）
- 延期高亮双条件：`未完成 && (超期 || reschedule_count≥阈值)`；阈值默认 3 可自定义；有次数显示「图标+数字」，无次数仅图标
- **验收**：三种拖拽计延期规则正确、高亮条件与阈值可配置生效

## M5 搜索与过滤
- 前端解析 `status:done type:plan` token（多值）+ 剩余文本对 名称/链接/结论 模糊匹配
- 后端组合查询（结合 owner 过滤与视图范围）
- **验收**：token 与模糊组合命中正确、多状态联合语义符合约定

## M6 AI 分析
- httpx 异步调智谱 GLM（OpenAI 兼容 `/paas/v4/chat/completions`，默认 glm5，密钥后端硬编码）
- 以当前筛选数据为 context，4 预设（进度趋势/分布/阶段性复盘/预测）+ 自定义提示词
- StreamingResponse SSE 流式渲染；大数据量字段裁剪与条数上限保护
- **验收**：流式输出正常、四预设可用、超大数据集有保护

## M7 部署 · 响应式 · 测试收尾
- 响应式适配 PC/移动；**对齐 `docs/index.html` 高保真原型视觉**：蓝色主色系、多层阴影与 hover 上浮、圆角、优先级三色 pill、延期徽章、AI 悬浮球 FAB、模态 pop 动画等设计 token
- Docker Compose 上线（caddy 自动 HTTPS + 反代 `/api`）、库与上传目录持久卷、定时备份
- 测试：单元测试随开发推进（UT-01~UT-10，见技术架构文档）；QA 执行 `测试方案.md` 功能/接口/权限/部署用例；全链路联调
- **验收**：线上可访问、备份可恢复、P0 用例全过

## 关键路径与并行建议
- **串行主线**：M0 → M1 → M2 → M3 → M4
- **可并行**：M5、M6 在 M2 完成后即可与 M3/M4 并行；测试从 M1 起同步编写
- **风险优先**：拖拽三语义（M4）与 AI 流式（M6）是难点，建议尽早各做一个技术验证（spike）
