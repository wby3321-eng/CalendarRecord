# CalendarRecord 测试方案与测试用例

---

## 一、测试概述

- **测试目标**：验证 Web 端各功能模块、关键业务规则、鉴权与数据隔离、非功能指标均符合需求。
- **范围内**：日历视图、节假日/调休、任务与类型管理、任务卡片、拖拽交互、延期高亮、搜索过滤、标签/标签云、报刊视图、用户竖栏、用户设置、AI 分析、注册登录与权限、响应式与部署冒烟。
- **范围外**：iOS/Android 独立 App；第三方（智谱 GLM、chinese-days）内部实现正确性（仅验证集成与降级）。
- **优先级**：P0 核心必过 / P1 重要 / P2 次要。

## 二、测试策略

| 类型 | 方法 | 当前状态 |
| :-- | :-- | :-- |
| 纯逻辑单元测试 | 前端 vitest + 后端 pytest | ✅ 已自动化（见「四、自动化测试点清单」） |
| 功能测试（UI/交互） | 手工 + 浏览器 | 开发期已逐项浏览器验证，正式回归见「五」 |
| 接口/权限/安全测试 | 手工为主（pytest+httpx 待补） | 数据隔离、越权、鉴权、注册限流尚未自动化 |
| 集成测试 | 手工 | AI 流式、节假日库、文件上传 |
| 部署冒烟 | 手工 | Docker Compose 起服务、持久化、备份恢复 |

## 三、测试环境

- 前端：Chrome / Safari / 移动端浏览器（含窄屏 375px）；开发地址 `http://localhost:5174/`。
- 后端：FastAPI + Uvicorn；SQLite（WAL）。
- 账号准备：1 个预置管理员（admin/admin123）+ 造 5 个普通用户（用于验证第 6 个注册被拒）。
- 数据准备：跨日 / 跨周 / 跨月 / 跨年任务各若干；含链接、长结论（>20 字）、图片/文件附件、标签、各内置与自定义类型。

## 七、缺陷管理与通过标准

- **缺陷分级**：致命（阻断主流程/数据泄露/越权）> 严重 > 一般 > 轻微。
- **通过标准（Exit Criteria）**：
  - 自动化单测 100% 通过（当前 33/33 ✅）；
  - P0 手动用例 100% 通过；P1 ≥95% 通过；
  - 无致命、无严重未修复缺陷；
  - 数据隔离与越权类（TC-PERM、TC-TYPE-06、TC-AUTH-05/06）全部通过（安全红线）。
